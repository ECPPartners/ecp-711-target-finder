# ECP 7-Eleven Target Area Finder — pipeline

**Scoring models are versioned in `models/` (see models/README.md for history and how to revert). Env `MODEL=<version>` runs an older one.**

Confidential to ECP Partners. Spec and build plan live in the claude.ai project "711 target area finder".

Run order (pilot counties), from a work dir with `dl/` and `out/`:
1. `01_atp_pull.py <run_id> dl/atp` — brand locations from AllThePlaces
2. `02_counties_stores.py dl/atp out` — FDOT county polygons + Florida store inventory
3. `03_fdot_pull.py out/fdot` — FDOT AADT/trucks, functional class, local names, signals, medians
4. `04_dor_download.py 2026 dl/dor <counties...>` — DOR NAL + parcel map zips
5. `05_tracker_geocode.py <tracker.xlsx> out/tracker_fl.csv` — ECP sales tracker FL rows
6. `06_parcels.py dl/dor dl/dor_x out/parcels <counties...>` — parcel points (res / vacant lots / commercial)
7. `07_network.py dl/atp out` — 7-Eleven network + tracker match
8. `10_fdep_stations.py out` — FDEP open retail fuel stations (run before 07)
9. `08_source_workbook.py out "<xlsx>"` then `09_format_xlsx.py "<xlsx>"`

Python deps: geopandas pyogrio pyarrow remotezip requests openpyxl
10. `11_candidates_score.py out "<source.xlsx>" "<result.xlsx>"` — candidates, scoring, tiers, backtest. Override weights with env SCORE_OPTS='{"weights":{...},"mf_weight":0.5}'

## Artifact
Front end lives in `artifact/` (index.html, app.css, app.js, vendor/leaflet.css). Data files are generated by
`11` + `12_artifact_data.py out "<source.xlsx>" "<step2.xlsx>" <dir>/data` and published to the claude.ai artifact
`b0ece350-ae01-4c2d-9013-37945df29fd0` ("7-Eleven Target Area Finder") with publish_files (mode patch, data/*.json only).
Capabilities: db (collections: reviews, packs, submittals), user (profile), sample, downloads.
11. `16_raw_corners.py dl/dor_x out out/candidates_scored_optionB.csv out/candidates_raw.csv <counties...>` — raw-land corner test (default filter, Nov 11 2026). `aerial_qa.csv` holds manual aerial-check exclusions.
12. (v1.1+) `17_wetlands_pull.py <candidates.json> out/nwi_wetlands.geojson` — NWI wetlands around raw corners
13. `18_land_screen.py dl/dor_x out/fdot out/nwi_wetlands.geojson <candidates.json> out/land.csv` — upland/frontage/owner screen
14. `19_trade_areas.py out/land.csv out/corners.csv out/areas.csv` — trade areas → best corners
15. `20_review_workbook.py out/land.csv out/corners.csv out/areas.csv <last_review.xlsx> <out.xlsx>` — deal-maker review workbook
Run 17–20 with `MODEL=v1.1`.
16. (v1.2+) `21_rail_pull.py out/fdot/fdot_rail.geojson` — FDOT rail lines for the rail warning
17. (v1.3+) `22_corner_options.py dl/dor_x out/fdot out/fdep_stations_fl.csv out/land.csv out/options.csv` — one-owner land, stations at the corner, road side
18. `23_top50_options.py out/options.csv reviews/corner_status.csv out/top50.csv` — Top 50 trade areas with a/b/c options
19. `24_top50_workbook.py out/top50.csv reviews/corner_status.csv <last_review.xlsx> <out.xlsx>`
Team-maintained inputs: `pipeline/manual_7eleven.csv` (7-Elevens the sources miss) and `reviews/corner_status.csv` (corners taken or passed).

Front end: `frontend/` holds the live tool page (index.html, app.js, app.css) as published with each model version; data files come from step 12 plus the Top N option fields.
